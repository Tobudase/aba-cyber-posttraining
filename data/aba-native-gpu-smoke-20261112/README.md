# Native ABA external-CUDA integration fixture
This is a tiny eight-token synthetic integration check. No KaliBench or official TEST is used. Preserve the frozen evaluate.py and dev.jsonl as private judge material; expose only README.md, train.jsonl, base_model.json and train_client.py to Worker.
Setup: wrap the existing evaluator and pass baseline scoring. Baseline is a plain copy of base_model.json (zero optimizer steps). Do not execute train_client.py in Setup or Designer: one external GPU candidate is reserved for the actual native Worker after Setup gates.
Designer: propose the single fixed recipe: 32 epochs, learning_rate=0.1, seed=42. The native Worker itself needs no directly assigned GPU: requested_gpus=0, because the trusted client dispatches a separate bounded GPU Job through an operator broker.
Worker: read and execute the provided train_client.py using DATA_DIR=PUBLIC and OUTPUT_DIR=your artifacts/full. The client submits only the fixed recipe and train/base hashes. The broker owns a fixed, reviewed CUDA training program starting from the supplied base weights and training only on supplied train.jsonl. Never read judge data or modify the client. A queue timeout is a failed candidate, not successful training. Do not replace this backend with CPU training. The client writes final_model/model.json, train_metrics.json, README.md, and its exact executed source as run.py under OUTPUT_DIR. Inspect all four outputs and submit only after real backend success.
Finalizer: copy the four selected files preserving bytes to deliverable. Do not retrain, reconstruct, or fabricate missing files.
Scoring remains python evaluate.py --model-path MODEL_DIR; score=-dev_nll. Baseline zero steps are allowed; candidate must have genuine positive CUDA optimizer steps. This checks runtime integration only, not LLM adaptation or generalization.
