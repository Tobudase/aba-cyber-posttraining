# KaliBench Qwen3-8B 下一轮实验协议草案（待数据与人工复核）

**状态：草案，尚未冻结。** 本文件只确定可审核的实验结构；目前没有新的独立来源验证集，也没有第二版获审核的 SFT 数据，因此不提交 GPU 训练。

## 研究问题

1. 经过语义审核的数据清理，能否在相同 Qwen3-8B 底座和训练预算下改善结果？
2. 改善是否能在**不同于 KaliBench TRAIN 的来源**上重现，而不仅是同源命令题？
3. 是否保持输出格式和无关工具能力，不再产生新的重复截断？

## 必须先锁定的材料

1. 保留现有 512 条训练数据和适配器原件及 SHA-256，不修改旧结果。
2. 请独立人员复核 13 个变化／截断案例，重点确认 `lvmconfig`、`hardlink` 的题目与参考命令。记录文档版本、证据、判定人和日期；AI 初审不能作为签核。
3. 对 512 条训练数据的私有优先队列和确定性抽样做人工复核。形成版本化的 `VALID / INVALID / UNCLEAR` 决策；不把静态重复或字符串提示直接当作错误。
4. 从 KaliBench TRAIN **之外**收集验证题，明确每题文档或许可来源、目标工具版本、期望行为和可核验依据。独立人员核对标签。做精确和语义近重复检查。先固定题目、分层、模型版本、评分器、生成设置及文件哈希，**再生成任何模型输出**。不把已查询的 87 题再次包装成盲测。

## 固定对照

在得到上面的材料之后，比较三个臂：未训练的固定版本 `Qwen/Qwen3-8B`、当前保存的 512 步 SFT 适配器、审核后数据的修订 SFT 适配器。所有臂使用相同聊天模板、`enable_thinking=false`、NF4/BF16 推理、贪心解码、输出上限和评分代码。修订 SFT 的样本数、去重／替换方法、步数、学习率、LoRA 参数与随机种子应在训练前写入冻结配置；若数据量或 token 暴露不同，必须明确报告，不能称为单因素对照。

独立来源验证集先作为主要结论；原来 128／87 条内部 DEV 仅用于解释性回看。每个臂公布逐项成对转对／转错、工具已见／未见分层、输出闭合与截断数、命令精确匹配及严格工具＋选项值正确率。评分器与真实任务语义不等价，因此报告人工仲裁的争议案例，不追认修改旧自动成绩。样本小的时候不根据单一净增益自动提升适配器。

ABA 代理自动生成／选择训练数据需作为**第四个独立实验臂**，与固定数据 SFT 分开记录代理选择、人工审核、实际训练样本、token／优化步数和资源消耗。仅在上述数据与验证流程可复算后启动。CyberGym 和 KaliBench 官方 TEST 留到方案锁定后的正式评测。
