# KaliBench Qwen3-8B：训练数据回执复核与探索性筛选（2026-10-29）

## 为什么需要这一步

原先 512 条 SFT 样本都带有发布方 `PASS_EXECUTED` 标记，终端退出码也都是 0。但重新只读检查发布方的标准输出、错误输出和截断标记时，发现部分回执文字含有“文件或目录不存在”“权限或设备不可用”“DNS／网络失败”等提示。因此 `PASS_EXECUTED` 能说明命令被执行并获得了发布方标签，**不能单独证明题目要求的实际效果已达成**。

相反，出现环境错误也**不能证明参考命令写错**：例如命令可能正确，测试容器却缺少指定文件、设备、显示服务或网络。以下筛选只用于探索性数据消融，绝不是逐题专家判错。

## 只读复核和派生数据

从原始冻结的 512 条 KaliBench 官方 TRAIN 记录出发，核对文件 SHA-256、题目／参考命令与发布方原始记录、Qwen 编码、目标 token 掩码以及 128 条内部 DEV 输入隔离。依照事先写明的**终端回执文本提示**分类，得到：

| 类别 | 条数 | 当前处理 |
| --- | ---: | --- |
| 无所列环境失败／截断提示 | 401 | 单独保存为探索性训练候选，仍是发布方银标。 |
| 有提示，需检查实际任务效果 | 111 | 保存私有待复核队列；不宣称全部错误。 |
| 独立人工判定 | 0 | 未将 AI 或规则筛选冒充为人工签核。 |

提示类别可以在同一条回执上重叠。64 条出现文件／目录不存在类提示，12 条权限／能力不足，16 条网络／DNS 不可用，2 条显示环境不可用，2 条缺依赖，36 条有显式错误行，另有 1 条发布方输出被截断。**这些数相加不能当作被筛除的条数。**[公开汇总与哈希](../results/kali-qwen-receipt-screen-2026-10-29/summary.json)不含逐题内容；私有目录保留 401／111 派生样本、512 条逐题提示清单与编码数据。

为能与原 512 步 SFT 做初步预算对比，另准备 512 步暴露计划：401 条候选各出现一次，按固定哈希选择其中 111 条再出现一次。它与原训练相同的是**优化步数**，不同的是**独立训练样本数、重复次数及实际 token 暴露**。后续任何前后对照都必须写出这些差异，不能声称只改变了标签质量。这个计划没有使用 DEV 模型输出或官方 TEST 来筛选训练样本。

工具覆盖的损失已经由[另一项静态统计](../results/kali-qwen-receipt-screen-2026-10-29/coverage-impact.json)量化：原 512 条覆盖 275 种工具，筛后 401 条仅覆盖 232 种，**43 种工具完全消失**。111 条暂缓样本中，有 91 条来自这 43 种工具，因此它们是优先人工复核与可能恢复覆盖的对象。原内部 DEV128 中有 20 题的工具不再被训练样本覆盖；先前的 DEV87 中则有 33 题。两种 512 步计划的总输入 token 接近（209,135 对 209,090），监督目标 token 为 10,620 对 10,719；这缩小了总训练量差异，但**不能抵消工具覆盖及独立题目数的变化**。因此若下一轮效果变差，工具覆盖损失是一种直接可能解释；若效果变好，也不能把全部收益归因于“标签变干净”。

## 有限探索性 SFT 结果

候选训练日程已实际用于一项**单张 RTX 3090、512 步 NF4 QLoRA** 有限作业。使用固定 Qwen3-8B revision、相同训练脚本、随机种子、学习率、提示格式和 128 条内部 DEV 输入。两次训练前的 128 条模型回答逐条相同；新作业完整结束，适配器和预测回执哈希已核对，自有 Job／Pod／ConfigMap 已清理。新作业约 2,130 秒，峰值 CUDA 已分配约 10.28 GB。本次只对原来已查询过的官方 TRAIN 内部 DEV 评分，**不是新的盲测**。[无逐题输出的对照汇总](../results/kali-qwen-receipt-screen-2026-10-29/comparison.json)和[复算脚本](../scripts/compare-kali-qwen-receipt-screen.py)记录计算方式。

| 内部 DEV128 自动诊断 | 原始 512 条 SFT | 筛选后 401 条不同样本、512 步 SFT |
| --- | ---: | ---: |
| 训练前严格正确 | 29/128 | 29/128 |
| 训练后严格正确 | **43/128** | **39/128** |
| 训练后精确参考命令匹配 | 36/128 | 32/128 |
| 训练后 512-token 截断 | 0 | 1 |
| 训练后完整 `<output>` 块 | 128 | 127 |
| 训练后原生 `total_score` | 69.10 | 66.69 |

训练后严格评分的成对比较：两者都正确 38 题、都错误 84 题、只有原方案正确 5 题、只有筛选方案正确 1 题。按工具覆盖分，筛选后仍有训练样本的 108 题为原方案 35→筛选方案 33；筛选后工具完全消失的 20 题为 8→6。可见退步既发生在失去工具覆盖的题，也发生在仍被覆盖的题，不能只归因于覆盖减少。

对 6 个分歧案例做了**AI 文档初审**：5 个原方案独有的自动正确案例，在当前公开工具说明中均能找到支持原方案、质疑新命令的依据；唯一“筛选方案独有的正确”案例还存在主命令参数位置的疑点。比如 `sn0int` 上游把 workspace 选项定义在父命令，且未标为可传给子命令的 global 参数；自动评分仍把筛选方案记为正确。这说明严格自动分数本身可能有假阳性。见[sn0int 源码](https://docs.rs/sn0int/latest/src/sn0int/args.rs.html)与[clap 全局参数说明](https://docs.rs/clap/latest/clap/struct.Arg.html#method.global)；其余工具依据包括 [Kali SearchSploit](https://www.kali.org/tools/exploitdb/)、[Kali smb2-quota](https://www.kali.org/tools/cifs-utils/)、[Kali IVRE](https://www.kali.org/tools/ivre/)、[lscpu 手册](https://man7.org/linux/man-pages/man1/lscpu.1.html)和[Kali John Mailer](https://www.kali.org/tools/john/)。目标工具版本尚未逐项确认，也没有独立人工签核；本次不追认修改冻结的 43/128 与 39/128 自动分数。逐题问题、命令和模型输出只保存在私有审查记录。

**决策：不采用这个 401 条筛选版本替代原 SFT 数据或适配器。** 它在复用的内部 DEV 上更差，且 111 条提示可能只是环境限制，并非错误标签。优先复核其中使 43 种工具消失的 91 条，按真实任务效果和工具版本逐条裁定；保留原始 512 条、旧适配器及旧自动结果。原来的 RedSage-K 正式默认模型也不因此改变。只有完成独立人工裁定，并在不同来源、先冻结的验证集上复现收益，才适合把派生数据提升为正式训练版本。13 个先前变化／截断案例的独立人工签核仍为 0，尤其 `lvmconfig` 和 `hardlink` 需要裁定。[前次静态审计](KALI_QWEN_TRAIN512_DATA_AUDIT_ZH_2026-10-28.md)与[下一轮协议草案](KALI_QWEN_NEXT_EXPERIMENT_PROTOCOL_DRAFT_ZH_2026-10-28.md)解释其余限制。

此步的回执检查和派生编码没有运行任何基准命令；后续 SFT 作业执行了模型推理与训练，但没有执行基准题目命令或使用官方 TEST。[筛选脚本](../scripts/prepare-kali-qwen-receipt-screen.py)可在持有许可的私有 TRAIN 文件和原始编码时重算。
