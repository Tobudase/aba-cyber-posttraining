# KaliBench 反复退化：选项写法、解析规则与监督覆盖的验证

这是对已经完成的 E0、P04、P05、P06、P07 预测所做的**事后只读诊断**。代码没有改动训练或正式评分，也没有读取官方 TEST、封存 final64、执行生成的命令或重新使用 GPU。[可复算脚本](../scripts/audit-kali-sft-syntax-20261111.py)只输出汇总，不公开逐题文本。

## 已证实的评分机制

冻结的 KaliBench 评分器只会在**参考标签声明某选项需要值**时，消费命令中该选项后面的空格分隔值。若模型写了标签之外的选项，`--other=value` 的值包含在同一 token 内，不进入位置参数；`--other value` 中的 `value` 则进入位置参数。一个无害的合成 `toy` 测试中，两种写法的工具名分均为 1、选项 F1 均为 0，但位置参数 F1 分别为 **1 和 0**。这验证了评分解析对写法敏感；它**不表示错误选项因使用等号就变正确**。实际 128 条 DEV 参考命令在该评分器下自评均为满分。

## 已观察到的训练与输出分布

旧 638 条 TRAIN 参考目标中，已知需要值的选项出现 **432 次空格写法、9 次等号写法**；新增 95 条中相应为 **63 次、2 次**。在 128 条同源、已暴露的内部 DEV 上，底座 E0 有 **24 题**生成“参考范围外选项＝值”，**10 题**生成“参考范围外选项 空格 值”。训练后的 P04/P05/P06/P07，前者分别仅有 **5/4/4/2 题**，后者分别升至 **35/37/35/35 题**。这与 SFT 使模型更偏向空格写法相符，但不是随机化因果证据。

在 P04、P05、P06 都比 E0 低分的固定 **29 题**中，P07 有 **25 题**生成参考范围外选项、**24 题**多出评分器解析的位置参数；E0 则有 **17 题**使用参考范围外选项的等号写法，而 P07 是 **0 题**。其中 **7 题**可直接看到 E0 的某个非参考选项用等号、P07 的**同名**选项改为空格。P07 的 29 题中有 **21 题**出现参考范围外选项后跟空格值；这类写法在所有 128 题中也显著增多。

其中 **4 题**还有更强的逐字证据：把 `--flag=value` 拆成 `--flag value` 后，E0 与 P04、P05、P06、P07 的完整命令 token 序列在这 4 题分别相同；实际表面写法不同。四个训练运行都在这同四题累计损失 **0.60317** 个原生分数单位。对这些配对预测而言，**写法及冻结解析规则足以解释观察到的分数差**，不需要假设模型换了工具或任务选项；这不表示这些命令在真实 CLI 中行为相同，也不说明其选项有效。其余 25 道反复退化题不能做这种纯写法归因。

对这 29 题做一个**纯诊断、非正式评分**的反事实：仅当非参考选项后的 token 同时是相对参考答案的多余位置参数时，假设不把该 token 计为位置参数。共涉及 **24 个 token**；19 题位置参数 F1 提高，29 题平均位置参数 F1 从 **0.39163** 变成假设下的 **0.86207**，有 **12 题**的假设总分不再低于 E0。这量化了解析交互可能解释的分数部分。它不是修复方案：这些选项仍可能无效，且有些 token 可能本来就应是位置参数；正式原生分数与严格正确数一律保持原样。

## 真实模型错误与数据覆盖

不能把退化全归咎于评分器。29 题中，参考答案要求 **78 组选项**，同工具的 733 条 TRAIN 只出现过其中 **35 组**；**15 题**的参考选项组在同工具 TRAIN 中一组都没有，只有 **9 题**的所有参考选项组均覆盖。P07 的参考范围外空格选项，在同工具 TRAIN 中未发现。因此现有数据虽覆盖 390 种工具，但对很多**具体任务选项**监督不足。训练也没有把这批错选项改为正确选项。

两个文档核对支持“模型选项错误确实存在”，而不仅是分词争议：[Pacu 官方仓库](https://github.com/RhinoSecurityLabs/pacu)的命令行说明列出 `--data` 以查询本地数据，没有列出模型在一例中使用的 `--list-data`；[Pocsuite 官方参数指南](https://pocsuite.org/guide/parameter-pocsuite.html)将 PoC 关键词筛选写为 `-k`，并将 `--vul-keyword` 用于不同的 Seebug API 路径，没有列出该例模型使用的 `--keyword`。这只是**两个个案**的文档证据，不能据此认定其余 27 题的每个选项都无效，也不能忽略工具版本差异。

对当前发布方 TRAIN 数据再做只读余量核对：954 条同时有 `PASS_EXECUTED` / `ACCURATE`，其中 936 条进入已筛选数据；733 条用于 P07/P08 训练，128 条用于内部 DEV，64 条封存，剩余 **11 条**按事先的数据去重与受保护命令组规则排除。另 **18 条**虽然有发布方通过标签，却因参考命令不能在原生评分器中自评满分而被原筛选流程保留在 hold，不能直接加入 SFT。这 18 条只与稳定退化组中的 **1 道**题属于同一工具，而且**没有**覆盖该组缺失的任何必需选项。因而当前筛选后的发布方 TRAIN 池里没有现成、可直接补上这批选项监督的新增样本；需要工具版本核验后的新数据，而不能把 hold 或 DEV/final 偷渡进训练。[去标识化来源余量审计](../results/kali-source-gap-2026-11-11/aggregate.json)和[复算脚本](../scripts/audit-kali-source-gap-20261111.py)。

## 根因结论与下一次实验

**已验证的直接机制**：现有训练目标强烈偏向空格分隔选项值；训练后输出同样转向这种写法。模型在部分题上仍选错或生成参考范围外的选项，冻结解析器便把其后值算成额外位置参数，产生可重复的 F1 退化。**尚未证明的上游因果链**：哪一批训练样本导致了错误选项；写法转移是否完全由 SFT 引起；某些非参考选项是否是不同工具版本中的有效别名。数值训练波动也仍影响 P04/P05/P06 之间的小幅差异。

下一次训练应在运行前冻结**同预算、同初始化的配对对照**：从官方 TRAIN 或工具官方文档中补充经过版本核验、覆盖具体任务选项的目标；一臂保持等量原数据，一臂替换为针对性高质量数据。训练与推理参数一致，并额外记录有效选项、位置参数及格式错误。先用未暴露的新开发题和安全离线 fixture 核验，最后只对明确选出的候选进行一次独立/官方评测。不能简单把错误选项改为等号写法来抬高分数，也不能把当前诊断反事实当作模型改进。
