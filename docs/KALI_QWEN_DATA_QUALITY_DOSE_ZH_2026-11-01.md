# KaliBench Qwen3-8B：训练数据质量与 734 步剂量试验（2026-11-01）

**运行更新：** 后续在 A40 上完成了两组各 734 步的固定 SFT 比较。已暴露的 utility confirm36 严格正确为 18→24，旧 domain DEV64 为 22→22；探索性门槛通过，但 15 道新增正确题全部集中于与训练语义重合的三个自编题型，故不推广模型。完整结果和离线执行核查见[结果报告](KALI_QWEN_DIVERSE_734_RESULT_ZH_2026-11-01.md)。

## 已核实的事实

1. 上轮等步数试验把 12 条自编、Linux 离线验证的 `grep` / `tshark` 样本加入 638 条原训练数据。新样本只占 650 次参数更新的 **1.85%**；在已暴露的开发集上，domain strict 为 22/64（对照）与 21/64（新数据），utility primary strict 均为 18/36。这个结果不能确定“数据无效”，只能说明**该剂量和方案没有观察到净收益**。
2. 为取得新的内部诊断集，我们在未进入旧 Qwen 拆分的官方 TRAIN 记录里固定了 96 题，且在任何新模型输出前检查了原始发布方验证字段。结果发现 88 题标为 `PASS_RUNTIME_ERROR`，8 题标为 `TIMEOUT`，**0 题**标为 `PASS_EXECUTED`。因此该面板和依赖它的第一版 734 步评测协议已撤回；没有对这些 96 题做模型推理。
3. 完整官方 TRAIN 3504 题中，终端标记为 `PASS_EXECUTED` 的有 954 题，`PASS_RUNTIME_ERROR` 有 2355 题，`TIMEOUT` 有 195 题。已有评分一致性筛选集共 3376 题，其中 936 题标为 `PASS_EXECUTED`，这 936 题已经全部属于此前 Qwen 的训练/开发拆分。剩余 18 条成功执行记录在筛选集之外，不能忽略原筛选原因直接使用。
4. 另行构造的 **96 条训练候选**覆盖六个此前出错的命令意图族，每族 16 个相关变体。其发布文档和 KaliBench 输出格式已检查，且 96/96 条参考命令在 Nautilus 的临时本地日志或合成 PCAP 上通过离线执行。检查 Job 为 CPU-only，已删除；没有执行模型生成的命令、联网扫描或官方 TEST。这些是**自编、狭窄环境的 silver 训练数据**，不是独立专家金标。

## 修订后的受控比较

两组均从同一个固定的 Qwen3-8B checkpoint 和 LoRA 初始状态开始，共享原有 638 条训练数据，再各做 96 次更新：

| 组别 | 增补内容 | 总更新数 |
| --- | --- | ---: |
| 对照 | 96 条长度接近的发布方 TRAIN 样本重复项 | 734 |
| 新数据 | 96 条离线执行通过的自编 `grep` / `tshark` 样本 | 734 |

新数据占更新数 **13.08%**。学习率、随机种子、Qwen 输出格式、推理设置及已暴露开发集保持一致。预先设定的**探索性门槛**是：新数据组在 utility primary 36 题至少比对照多 3 题正确；旧 domain DEV64 至多少 2 题；不能增加截断；官方 TEST 保持未查询。即便门槛通过，也**不会自动推广模型**，因为开发集已被反复查看，且缺乏独立来源的可靠验证。

增补部分的总输入 token 为对照 **39,309**、新数据 **39,216**；受监督输出 token 为 **2,155** 与 **2,208**。两组并非严格 FLOPs 相同，但额外数据的长度接近，有助于区分“只是多做了更新”和“更新来自不同数据”的影响。

## 当前限制

- 这 96 条训练样本只覆盖六种意图，且同族样本高度相关。它们可以检验“增加正确示例剂量是否修复这些退化”，不能证明对更广泛 KaliBench 工具的泛化。
- 发布方 `PASS_RUNTIME_ERROR` 不一定意味着问题或命令错误；它也可能表示缺少目标文件或环境。这里拒绝把它们当作计划中的“执行成功”面板，是为了保持证据等级一致。
- 固定步数与近似长度匹配不意味着完全相同的 FLOPs、梯度分布或训练语义。
- 官方 TEST、NL2SH-ALFA 保留的 TEST 及 CyBashBench AI-only 诊断集均未用于本次模型选择。
