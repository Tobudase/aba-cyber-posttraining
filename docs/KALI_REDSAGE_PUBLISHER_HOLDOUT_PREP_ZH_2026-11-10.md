# RedSage-K：KaliBench 发布方 TRAIN 内部留出实验准备

## 为什么更换诊断数据

C13 使用的 240 条自编训练题仅覆盖 `grep`、`wc`、`head`、`tail`、`jq`、`openssl`、`tshark`、`tcpdump`。在本项目筛选的 KaliBench 发布方 TRAIN 中，这八种工具没有任何 `PASS_EXECUTED` 样本。C13 在自编 DEV72 上的提升（29/72→44/72）集中于两个相近的六题模板组，不能据此推断它提高了 KaliBench 目标能力。原拟运行的 26 题 CyBashBench 检查也主要测试通用 Bash 工具，且参考答案仅经 AI 筛查。因此在第三次 GPU 任务排队、尚未分配 GPU 时撤销，并确认相关 Job、Pod、ConfigMap、Secret 均已清理。

## 已冻结的目标对齐比较

- 数据源：固定版本的 KaliBench 发布方 TRAIN；仅取终端验证 `PASS_EXECUTED` 且模型验证 `ACCURATE` 的记录。发布方标签属于 silver，未由独立专家逐条复核。
- 训练候选：此前使用过的 638 条发布方 TRAIN，覆盖 359 个工具。使用固定版本 RedSage 分词器重新编码，原生 `<think>` 输入后监督空思考闭合、`<output>` 命令及 EOS。编码已完成；训练未启动。
- 内部留出：固定种子选出 64 题，排除上述 638 条及旧 DEV64 的 ID；与 638 条训练题的工具加规范化命令组也不重合。56 题涉及训练中出现过的工具，8 题涉及未出现的工具。推理输入中不含答案。
- 模型比较：相同基础权重、LoRA 初始化语义、分词器、BF16、批量大小 4、贪心生成及 1024-token 上限，比较原始模型和现有 C13 适配器。每组附四条历史锚点以检查加载行为。
- 评分：固定 KaliBench 原生 `score_one`；另报严格选项值正确、格式错误、截断及配对得失。64 条参考命令自身均通过原生精确匹配和严格选项值检查。只解析输出文本，不执行模型生成的命令。

单 GPU 普通优先级推理 Job 已提交至 Nautilus，设七天排队上限、两小时 Pod 运行上限和一天结果留存。第一版西部任务在未调度时撤销；第二版在中央区域 A10 上完整校验了模型文件，但**首批历史锚点推理**出现 `CUBLAS_STATUS_EXECUTION_FAILED`，没有产生 64 题的预测。仅凭此错误不能断言唯一根因是显存或驱动。失败任务已清理。仅请求 L40/L40S 的第三版未调度，已在提交 A100 版本之前撤销并清理。此前同一 RedSage 基座的 C04 在 A100 上成功完成训练与推理，因此第四版改用一张 A100；服务端 dry run 通过，当前仍在排队。**尚无这 64 题的模型得分**。

下一轮 638 步 BF16 LoRA SFT 的优化器、数据、分词器、推理及评分协议已在这些模型输出出现之前固定，单 GPU 训练 Job 的服务端 dry run 已通过；为了避免同时请求两张 GPU，训练 Job 尚未提交。官方 TEST 使用为零；本轮尚无新的优化步骤。结果出来前不提升 C13。

这个内部留出集虽然在 C13 输出之前冻结，但选题发生在先前 DEV 观察之后，且仍来自同一发布方 TRAIN。它可用于判断后续 SFT 方向，不能等同独立来源验证、正式准入签核或官方榜单结果。
