安全审查器在遇到未知语法时同时把 `explicit_constraint_failure` 设为 true，作为拒绝执行的默认值；这个布尔值不能单独证明命令真的违反题目要求。不能根据该字段把 47 条全部改判为错误。保守门槛仍按原定义计算：`60 − (19 + 47) = −6`，仅 1 个意图组的保守净增为正，低于预设的 2 组要求。审计汇总由 `scripts/audit-kali-confirmation-posthoc.py` 生成，私有输入与结果的 SHA 保存在本地回执；公开版只含计数和来源承诺，不含任务正文、ID 或命令。

## 下一轮数据收集：先证明来源与答案质量

1. **建立独立任务来源。** 从正式工具文档寻找可核查的语法和功能，例如 [Wireshark TShark 手册](https://www.wireshark.org/docs/man-pages/tshark.html)、[jq 手册](https://jqlang.org/manual/)和 [OpenSSL x509 手册](https://docs.openssl.org/master/man1/openssl-x509/)。文档是语法依据，不自动成为独立测试集；任务题面与本地离线证据文件需要另行编写、记录作者和来源。先核查每个外部材料的使用许可，不复制未审查的数据集正文。
2. **分离来源与意图。** 每条任务记录来源 URL/版本、来源家族、作者或生成器版本、工具、意图、证据文件 SHA、标准命令、可验证输出和人工审查状态。训练、开发、锁定保持集必须在来源家族、意图模板、原始证据文件及完整题目上隔离。只做精确哈希排重，不从已暴露的 72 条确认题中挑选或修改新题。
3. **ABA 仅产训练候选。** Agent 可以提议题目、离线证据文件和目标命令；先静态检查只读工具、无网络目标、无任意 shell 复合执行，再在一次性隔离环境中运行金标准与负控制。失败候选、审查原因和成本都要保留。独立审核通过的样本才可进入 SFT；Agent 不读取锁定保持集或官方 TEST。
4. **先做小批次数据质量检查。** 每个工具家族先提出少量不同意图样本，逐条核对题意、标准命令和实际输出，记录重复率、语法可审查率与人工驳回率。未达到质量门槛时继续修数据，不启用 GPU 训练。小批次只验证流程，不能用于声称模型提升。
5. **冻结后再训练和评价。** 固定底座 revision、BF16 LoRA 配方、原生提示词、token 目标、推理参数、资源预算、评分器与决策门槛；先跑同卡底座，再训练一个候选，只用开发集迭代。现有 24 条历史保持题及 72 条确认题只能列作已暴露诊断；新锁定保持集只在最终配方固定后开启，官方 KaliBench TEST 留到最后。
