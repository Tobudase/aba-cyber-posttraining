# KaliBench 新任务质量门槛复核（2026-10-28 Pacific）

## 这一步做了什么

对上一轮 NRP `qwen3-small` 提出的两条已通过本地白名单的合成 jq 任务，保持命令不变，把输入事件改为五组预先定义的合成变体：原件、倒序、增加新低严重度事件与协议、移除低严重度事件、空事件列表。每次以独立 Python 逻辑计算期望 JSON，任务命令逐次在临时目录中只读运行。**2 条 × 5 组 = 10 次，10/10 通过。**那条意图不一致的候选始终没有执行。本轮没有 Linux/GPU Job、模型训练或官方 TEST 调用。

这比只核对一个固定输出更能检查命令是否真的响应输入变化，但只覆盖两种狭窄的 jq 意图。模型提出的题目仍存在格式说明不足：`low_ids` 没说输出 JSON 数组，`unique_protocols` 没说排序。上一批九条操作员编写的任务中也有排序、空数据和 OpenSSL 输出格式问题，已列入私有 AI 初审。**AI 初审和变形测试不能替代独立人工审核；可进入 SFT 的新样本仍为 0。**

## 来源与 ABA 状态

这些任务、问题和合成夹具为本项目自行编写／模型生成，公开手册仅用于核对命令语法，没有复制手册正文。[jq 项目说明](https://github.com/jqlang/jq/blob/master/README.md)记载其文档采用 CC BY 3.0；[OpenSSL 项目说明](https://github.com/openssl/openssl)记载其 3.x 仓库采用 Apache 2.0。若以后从这些文档摘录正文，需要按相应许可办理；当前候选不含此类摘录。来源许可与语义准确性仍应由独立审核者签认后再进入训练。

核查已有原生 ABA 任务配置发现：设计器被明确限制为固定训练脚本回放，禁止数据生成；运行桥接也声明 `search_enabled=false`。因此，前一轮 NRP 工具调用是**模型辅助候选生成**，不能写成原生 ABA 数据生成。要测试原生 ABA 创造数据，需要另立受控任务和权限边界，保留外部模型请求、文件执行与训练/评测分离，并在任务启动前冻结评测协议。当前未启动这种新运行。
