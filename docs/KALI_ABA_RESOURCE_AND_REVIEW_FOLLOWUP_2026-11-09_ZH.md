# KaliBench ABA 后续：复核时限与 GPU 调度

日期：2026-11-09（太平洋时间；部分集群记录为 11 月 10 日 UTC）。这是资源与编排诊断，不是新的模型效果结果。官方 KaliBench TEST 始终未查询。

## 原生 ABA 编排

- 一轮重试中，Setup 的外层预算和 reviewer 的内层预算同为 20 分钟。自动 verifier 已通过，但 reviewer 尚未结束时外层 Setup 截止，因而本轮在训练前失败。
- 将外层 Setup 调整为 40 分钟、保留 reviewer 的 20 分钟独立预算后，自动 verifier 再次通过，Setup 完成并进入搜索；reviewer 自身仍在 20 分钟上限耗尽前未给出通过结论。训练桥接器要求 verifier 与 reviewer 均明确通过，因此没有创建新的候选训练 Job。这两轮均不能算作完成原生 ABA 多候选搜索。
- 两轮停止后复查：没有个人 Job、Pod、ConfigMap 或 Secret 残留，控制 VM 已停止；正式 TEST 调用为 0。

## GPU 可行性与实时容量

- 保持普通优先级、单 GPU、2 CPU、12 GiB RAM、24 GiB 临时存储和同一缓存卷，做了短时调度探针。中央区一轮 RTX 4090 探针实际运行成功，显示 **24,564 MiB** 显存，缓存卷挂载成功；宽范围探针也曾分配到西部 RTX 4090 节点并完成缓存卷挂载，但在 100 秒探针上限时尚未执行 GPU 命令。
- 对未运行候选只调整了允许的 GPU 型号和调度地区，训练数据、底座、优化器、评分协议与 TEST 隔离未变。C13 的新 Job 清单通过 Kubernetes 服务端 dry-run。
- 固定中央区 RTX 4090 的 C13 正式训练尝试等待约 3 分钟仍为 Pending，主动停止并清理。随后放宽到兼容的 24 GiB 及以上 GPU 池，C13 连续 Pending 约 902 秒，触发预设调度超时。调度器显示兼容节点的 GPU 已占用，同时还有节点污点、CPU、内存与节点匹配限制。**两次 C13 尝试都没有开始优化器更新，没有新适配器或新分数。**
- 其他短探针覆盖西部和东部的兼容卡池；在检查时也因无可调度 GPU 而 Pending。所有探针均有时限并已清理。GPU 配额不等于实际空闲容量。
- 随后对同一冻结的 C13 配置又做了一次有时限提交：兼容 GPU 池连续 **约 910 秒 Pending**，没有优化器步骤、适配器或开发集分数，达到时限后自动清理。另一个普通优先级、单卡 A100 短探针在 **100 秒** 内也未调度，随后自动清理。这是当时的容量观测，不代表 A100 配额未获批准。

## 当前结论

历史 C02/C04 开发集结果不变，仍未达到冻结的探索性采用门槛；默认继续使用 E0。新的 C13 训练和原生 ABA 多候选搜索仍未完成。第二次 C13 超时尝试已单独归档；最终复查个人 Job、Pod、ConfigMap、Secret 均为 0，控制 VM 已停止。下一次应先获得一张可稳定调度的兼容 GPU，并把 reviewer 的工作范围与时限单独修正和验证；随后完成 C13 训练、开发集评分，再决定是否继续原生搜索。正式 TEST 保持封存，直到预先规定的最终评测阶段。
