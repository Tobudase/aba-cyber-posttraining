# KaliBench 训练侧：原生 ABA 生成新操作任务的小规模试验（2026-11-02）

## 本次实际完成了什么

在 Nautilus 上运行了**真实的 ABA 原生控制器**，包括 Setup、Designer、Worker 和 Finalizer，而不是固定提示的一次模型改写。控制器在 CPU 临时虚拟机中完成一轮候选搜索，正常退出并交付 `candidates.jsonl`。共得到 16 条英语问题与 CLI 命令配对，四种工具各 4 条。运行约 18 分钟（12:29:40–12:47:54 UTC）。本次没有训练或评测 Qwen3-8B；ABA 控制器使用的托管模型与待后训练的 Qwen3-8B 应区分。

为绕过之前的 LINSTOR 根卷挂载故障，临时虚拟机改用无 PVC 的容器磁盘与短期空盘。原生 ABA 的依赖和执行器在客体系统中完成安装；运行结束后收集候选和状态回执，并删除虚拟机，回读确认不存在。此次资源用量为 2 CPU、8 GiB 内存、0 GPU；官方 KaliBench TEST 行、验证集行和训练优化器更新数均为 0。ABA 日志显示的 `$0.00` 是**缺少该模型计价规则**，不能当作真实零成本。

## 冻结任务与原始结果

在任何候选输出之前，任务文件与评分器已写入哈希清单。只给控制器八条既有 TRAIN 例子作上下文：`head`/`tail` 取**字节**、`wc` 数**单词**、`grep` 做**区分大小写的整行**匹配。要求生成的四类新操作是：`head`/`tail` 取**行**、`wc` 数**行**、`grep` 做**不区分大小写的固定子串**匹配。题目、文件名、允许的参数形式和安全边界均有限定；不能把这 16 行称作开放域自主发明的网络安全任务。

## 研究结论与下一门槛

这次解决了一个具体工程障碍：原生 ABA 能在 Nautilus 上完成受控任务生成、私有评分和交付，而不依赖故障中的 PVC。四类新操作相对原始八条 TRAIN 例子确有语义变化，且在有限安全夹具中能执行。但 16 行几乎只是四个模板各换四个文件名，无法说明它们会提高 Qwen、KaliBench 排名或跨工具泛化。原 680 步托管模型改写实验的 10/16 对 10/16 结论保持不变；两个试验的数据与控制器不同，不能合并成一个“ABA 后训练增益”。

**当前决定：暂不把这 16 条投入正式 SFT，也不提升任何适配器。**下一轮应先扩展到更多真实不同的工具意图和约束组合，对每条问题、命令及输出作独立语义核验，并预先冻结与生成源分离的评测集。然后用同一 Qwen3-8B 初始权重、相同步数、近似相同 token 预算比较原 TRAIN 重复数据与 ABA 新数据，同时报告领域表现、通用 CLI 保留率和截断率。若只能使用已曝光开发集，应明确写作探索性工程对照，不能当成独立提升证据。
