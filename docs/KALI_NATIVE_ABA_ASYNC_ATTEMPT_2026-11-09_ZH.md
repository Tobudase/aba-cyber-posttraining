# KaliBench 原生 ABA 重试：接口恢复，候选等待 GPU 超时

日期：2026-11-09。本文记录一轮最多 3 次评估、串行单 GPU 的探索性试跑。它没有产生新的训练结果，也没有使用官方 KaliBench TEST。

## 已验证的部分

- 新 NRP 凭证可列出模型，极小的实际生成请求返回 HTTP 200。此前的控制器 HTTP 403 阻塞已消除；凭证本身没有公开。
- 原生 ABA Setup 的 verifier 与 reviewer 均通过，冻结选择指标为 `frozen_adoption_gate`、方向为 `max`。
- ABA 设计器选择预登记的 C13：RedSage-K 8B、学习率 1e-5、240 条自编合成 TRAIN 数据、240 优化器步、seed 42。选择过程没有改动数据、底座或评分协议。
- Worker 成功执行短 `submit` 调用并多次执行 `wait`。此前单次训练请求超过 Bash 两分钟上限的问题，在这次提交和状态查询链路中没有重现。

## 停止原因与结果

唯一的 C13 Job 请求 1 张 A100，使用普通优先级。Pod 始终为 `Pending / Unschedulable`；调度器报告符合条件的 A100 节点当前没有空位。等待约 911 秒后，宿主训练脚本按上限返回 `TimeoutError`，ABA Worker 收到失败状态。本次没有完成任何 C13 优化器步，没有模型适配器或开发集分数，也不能算作完成一次 ABA 候选评估。

失败后停止了本次原生 ABA 运行。C13 宿主记录显示剩余自有资源为 0、清理错误为 0；复查集群无自有 Job、Pod、ConfigMap 或 Secret，控制 VM 状态为 `Halted / Stopped`。官方 TEST 调用为 0。此前两次人工配方试跑 C02/C04 的分数不变，仍未通过准入门，因此保留原始 E0 模型。

下一次运行需要先确认一张合规的 GPU 可调度，再使用新的候选尝试目录重启有限时原生 ABA；不能把这次排队超时写成训练成功，也不应重复使用失败目录而不审计。当前仍缺真正完成并评分的原生 ABA 候选，以及独立验证。
