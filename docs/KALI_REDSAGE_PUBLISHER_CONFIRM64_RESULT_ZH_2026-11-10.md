# RedSage-K：第二组发布方 TRAIN 内部确认结果

在第一组 64 题显示发布方 SFT638 比基座多 2 题严格正确之后，我用**不同的固定种子**从剩余发布方 TRAIN 记录中选取 64 题，再运行基座与已保存的 SFT638 适配器。新题在本轮模型输出前冻结，与 638 条训练数据、旧 DEV64、第一组 64 题的 ID 及工具加规范化命令组不重合；答案没有进入推理输入。选题发生在第一组结果已知之后，所以它是第二组内部确认，**不能称作完全独立、事先统一预注册的最终测试**。60 题的工具见于训练，4 题的工具未见于训练。64 条发布方参考命令通过冻结的原生和严格评分器自检。

基座与 SFT638 在**同一张 NVIDIA A100-SXM4-80GB**、相同输入和生成设置下推理；同一模型权重、分词器及适配器哈希经过检查。历史基座锚点与旧 L40S 有 3/4 逐字一致、4/4 最终命令一致；跨设备解释文字的微小变化不进入主要的同机成对结论。

| 第二组 64 题 | 基座 | 发布方 SFT638 | 成对变化 |
| --- | ---: | ---: | ---: |
| 严格选项值正确 | 19/64 | **22/64** | 新增 7、失去 4 |
| 原生精确匹配 | 20/64 | **22/64** | 新增 7、失去 5 |
| 原生总分均值 | **0.7537** | 0.7197 | 下降 0.0340 |
| 格式错误 | 2 | **0** | 减少 2 |
| 截断 | 0 | 0 | 不变 |

60 条训练见过工具的题目严格正确 **18/60 → 22/60**；4 条未见工具为 **1/4 → 0/4**。失分较大的案例包括 `sprayhound` 和 `hashid`：基座给出了参考评分器认可的选项，SFT 改成缺失或错误选项。也存在真实的格式与命令改善，例如 `getconf` 和 `sn0int`。逐题分析只检查输出文本和自动评分，没有执行生成的命令或进行独立专家语义签核。

将两组各 64 题作**描述性合并**，基座与 SFT638 的严格正确是 **47/128 → 52/128**，原生精确匹配 **49/128 → 53/128**，原生均分却是 **0.7550 → 0.7510**，格式错误 **5 → 0**。严格正确的配对变化为新增 10、失去 5；未见工具合计 **4/12 → 3/12**。这些指标不支持宣称 SFT 全面提升目标能力，尤其不能把格式改善等同于命令语义改善。

因此继续保留原始基座为正式默认，新 SFT638 仅是研究候选。官方 KaliBench TEST 查询仍为零，任务和所有个人 GPU 资源已清理。原生 ABA 多候选自动搜索仍未完成。公开的[聚合 JSON](../results/kali-redsage-publisher-confirm64-2026-11-10/summary.json)不含题目、预测、参考命令或密钥。
