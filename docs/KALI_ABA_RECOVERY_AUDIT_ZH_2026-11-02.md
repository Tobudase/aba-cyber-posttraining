# KaliBench ABA 训练失效排查与下一轮准入（2026-11-02）

本次只读复核已完成的 Qwen3-8B 实验，没有重新训练或查询模型。原始预测重新评分后，已曝光的 16 题严格正确仍为底座、匹配对照、ABA 数据处理组各 **8/16**；指定 CLI 开发题集的两种 SFT 均为 **66/108**。这些数字没有发现计数错误，但它们都不是官方 KaliBench TEST 或独立金标结果。

## 可确认的故障现象

- 在同两道 `tcpdump` 开发题上，底座正常结束，两个 SFT 适配器都生成重复选项直至 **512 token** 上限，且没有关闭 `<output>`。指定 CLI 开发题集中两组 SFT 也各有 **6/108** 个未闭合、重复尾部的截断。完整训练记录中，每条样本的输入掩码、监督目标以及终止 token 均存在；这排除了明显的“忘记监督 EOS”编码错误，却不能证明模型实际学会结束。
- 更早的**仅 638 条共同训练数据**的已完成实验，在相同 108 道 CLI 题上记录了底座截断 **0**、SFT 后截断 **6**，且正是同一组六道 `grep` 行号题。已核对输入文件哈希，以及模型版本、生成上限、提示后缀、精度与种子均一致。这说明新增的 14 条 ABA 数据**不是这六次截断出现的必要条件**；仍不能仅凭现有记录判定是训练样本、优化过程还是解码交互的哪一环导致循环。
- 早先另一轮 680 步试验，CLI 题集的对照组截断 6、处理组截断 1；该轮的数据数量和组成不同，不能作为单变量因果证据。当前 652 步两组同样重复，提示要检查共享训练配方、数据覆盖与生成行为，不能只归咎于 ABA 新增行。
- 原生 ABA 的 **4 条 `grep` 候选**均以 *literal word* 描述本应允许嵌入更长字符串的固定子串匹配。其中 **2 条**进入 SFT，另 2 条因冻结评分器大小写敏感问题被排除。之前的 14/16 准入分数与已执行训练保持不变；未来候选应全部按语义歧义拒绝或明确改写。
- ABA 行仅占处理组 **14/652 次更新（2.15%）**、约 **1.57% 监督目标 token**，并且只有四类高度模板化操作。这样的实验不足以推断大规模、多样化 ABA 数据的潜力。

## 已完成的修复准备

从原始候选另存了一份明确标为**事后人工改写**的 16 行诊断副本：四条 `grep` 问题改为明确的“固定字面量子串、忽略大小写、可出现在更长字符串内部”。原始命令不变；在本机受限文件上完成 **32/32** 次双夹具执行核对。这不是原生 ABA 的原始输出，也没有进入训练。整批仍只有四种模板，**目前可准入的新训练行是 0**。Linux 环境、更多样的操作和独立来源评测尚未完成。

## 下一轮启动条件

1. 先冻结更广的 TRAIN 生成任务、逐题语义验收与受限 Linux 执行，明确“子串 / 整词”“正则 / 字面量”等区别；剔除含糊题目，保留来源和改写记录。
2. 再冻结与生成来源分开的新开发题及其参考输出；同时预设严格命令指标和安全执行的功能指标。已曝光的 16、64、108 题只作诊断，不作为新的盲测。
3. 用小型检查点对照定位重复输出首次出现的训练阶段，再运行固定底座、相同初始适配器、步数与 token 预算的匹配 SFT。报告至少两个随机种子、截断、逐家族正确率及功能结果。
4. 只有预设的新开发指标改善且原有功能没有实质退化，才考虑后续模型选择；官方 TEST 保持未使用。当前处理适配器不推广。

这是一次故障定位和数据准入修复准备，**没有确认唯一根因，也没有新的性能提升**。本次没有启动 GPU 作业；没有声称人工专家复核或独立金标。
