# KaliBench ABA 多候选搜索：两配方试跑与控制器阻塞

2026-11-09。以下是**已曝光、自编开发集上的工程试跑**，不是官方 KaliBench TEST 成绩，也不是 24 小时或 27 候选 ABA 搜索。

固定开源底座为 RedSage-K 8B。使用同一批 240 条经合成夹具检查的自编 TRAIN 题；120 步配方使用预先固定的前 120 条。开发评分使用 DEV72，通用能力保留检查使用 retention24。两份数据都已曝光，不能支持独立泛化结论。原始模型 E0 的选择分数为 0；不满足预设准入条件的候选分数为 -1。

| C04 | lr 5e-6、240 步、seed 42 | A100 | 240 | 28/72 → 26/72 | 11/24 → 12/24 | 112/112 → 112/112 | 未通过 |

两次训练分别改变 144 个适配器张量，保存后重新加载的对数值差为 0，适配器 SHA-256 不同。各自完成 224 次预测生成与安全合成夹具评分；没有官方 TEST 调用、外部教师调用或遗留 Job/Pod。C04 起初在普通 GPU 队列中只停留 Pending；改用一张获准的 A100 前保存了该次无模型输出的记录，训练数据和评分规则未变。C02 与 C04 使用不同 GPU，且基础模型在 retention 上的 12/24 与 11/24 有波动；因此只比较每个候选内部的训练前后变化，不把两个候选的绝对分数直接解释为配方因果差异。

随后准备了最多 3 次评估、串行单 GPU 的**原生 ABA 小规模试验**。控制器的任务文件、配置、桥接器与 Setup 审核门已通过静态和远端配置检查。第一次正式启动在 Setup 阶段终止，原因是 NRP 托管模型的生成请求返回 HTTP 403；它没有提出或训练任何新候选。独立无害检查发现同一本地令牌仍可列出模型，但 `qwen3-small`、`qwen3` 和 `gpt-oss` 的极小生成请求都返回 403，涉及 Anthropic 与 OpenAI 兼容入口。控制 VM 已停止，集群中无遗留自有任务。下一步需恢复 NRP 的模型生成权限，再启动**新的**有限时 ABA 试验；不能把 C02/C04 手动试跑计入 ABA 候选数。

结论：两候选端到端训练与评分链路已验证，**当前没有可提升的候选**；保留 E0 原始模型。仍缺原生 ABA 多候选结果、独立验证及官方 TEST 一次性最终评测。
