Linux 验证只运行普通优先级 CPU Job：**1 CPU、2 GiB、0 GPU**，约 67.5 秒。两条通过准入的 TShark 命令仅通过 `-r` 读取本项目生成的 pcap，使用 `-n` 禁用名称解析；没有实时抓包、外部目标或写出文件。Job、Pod、ConfigMap 与 Secret 均清理后复查为 0。Mac 没有 TShark，因此不把 Linux 的 10 次运行称为跨平台复现。

题目关键词初筛为 4/5；另一条使用字段名 `src` 而非英文 `source`，属于启发式检查不匹配，不能直接判定语义错误。私有审核队列列出六条题目、命令、证据和签核栏，供独立审核者审查输出格式、等价答案、许可与实质近重复。精确哈希无重叠不证明语义独立；这些任务仍共享我们编写的合成模板，也没有来源独立的锁定保持集。

## 可得出的结论与下一道门槛

本轮证明“冻结任务意图 → 模型辅助提出候选 → 严格只读命令准入 → 多输入离线验证 → 保留拒绝记录”的工程流程可用于 jq 和 TShark。由于标准命令事先由操作员冻结，不能把它描述为模型独立发现新命令或**原生 ABA 自主数据生成**。零条候选已经取得独立人工金标；没有新增 SFT、GPU 推理或官方 TEST 调用，先前保守确认门槛仍失败，正式默认模型是原底座。

后续先由未参与生成的人逐条审核并记录修订；再由不同来源制作锁定保持集，冻结 ABA 数据生成与 BF16 SFT 方案后才训练。已有 72 条确认题已揭晓，不能重新作为盲测。公开仓库只上传汇总、来源和哈希；原始候选、合成夹具、逐题执行记录与审核队列留在本地。
