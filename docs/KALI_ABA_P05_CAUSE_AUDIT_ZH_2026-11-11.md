# KaliBench P05 退化诊断：哪些原因已证实，哪些仍是假设

本报告只重新计算已有 P04、P05 的冻结内部开发集输出，不生成新预测、不训练，也不调用官方 TEST。封存 final64 只读取不带答案的题目 ID，以检查数据分离；未读取其参考答案或模型输出。数据标签来自发布方 silver，不能视作独立专家 gold。完整可公开的汇总在[结果文件](../results/kali-aba-p05-cause-2026-11-11/aggregate.json)；[审计脚本](../scripts/audit-kali-aba-p05-cause-20261111.py)需要未公开的私有预测与标签才能复跑。

## 直接证据

KaliBench 原生总分是工具名、选项 F1、位置参数 F1 的等权平均。P05 相对原底座 E0 的三个分项分别变化 **+0.03906、+0.01018、−0.05667**，因此总分从 **0.75499 降至 0.75252**。严格正确数却从 **47/128 升至 51/128**：10 题由错变对，6 题由对变错。这两个指标没有矛盾，因为两次都错的 71 题中也有部分得分变化。P05 的主要可见损失集中在位置参数分。

位置参数 F1 降低的 28 题中，27 题的预测命令在评分器解析后出现了多余的位置参数；14 题的参考答案根本没有位置参数。该解析器只把**参考答案已知的带值选项**后面的词当作选项值；模型如果生成未被参考答案识别的选项，其后面的词就会被解析为位置参数。这是评分下降的一个直接机制，并不证明模型有意添加了多余参数，也不证明解析器有 bug。题目语义和命令有效性仍需独立核验。

638 条训练目标逐条用锁定的原生评分器自评，**638/638 得满分**；因此没有发现训练目标整体与该评分器格式不兼容的错误。P05 训练后 **127/128** 个输出包含预期的 `</think>` 和 `<output>` 标记，而原底座没有 `</think>`；格式学会了，但这不足以保证命令选项和位置参数正确。

补充检查：638 条训练提示归一化后均不同；128 条开发提示也均不同，训练与开发没有完全相同的提示，亦没有相同的“工具名＋归一化标准命令”组合。这排除了这两类直接重复，但不能排除同一工具或相似任务的语义重叠。

## P04 与 P05 为什么不同

两次运行的模型权重哈希、私有训练/开发载荷、优化器（638 步、学习率 `1e-5`、seed 42）、LoRA 配置、初始化 seed、推理 seed、A100-SXM4-80GB 和依赖版本一致。Worker 的代码差异只在训练结束后的公开回执增加 `changed_tensors` 字段。它们的底座输出 **128/128 完全相同**；训练后输出 **110/128 相同、18/128 不同**。仅这 18 题解释了 P04 的 0.77569 与 P05 的 0.75252 的全部均分差异。

记录的第一步前向 loss 相同，第一步梯度范数已不同；20 个共同记录点中仅第一步 loss 完全相同，没有任何梯度范数完全相同。这证明两次训练数值轨迹早期就分叉，**尚不能确定**是 CUDA 非确定性、底层算子、并发环境还是其他未记录因素。单次 P04 的正向开发集结果不能当作稳定增益，也不能归给 ABA；P04 由操作员运行，P05 才是 ABA 选中的候选。

当前 Worker 设置了 `torch.manual_seed`，但没有启用 `torch.use_deterministic_algorithms(True)` 或记录初始 LoRA 权重哈希。与本实验使用版本对应的 [PyTorch 2.8 可复现性说明](https://docs.pytorch.org/docs/2.8/notes/randomness.html)明确指出：相同 seed 不保证跨次 CUDA 结果一致，确定性算子及 cuBLAS 环境还需单独处理。后续精确归因应在同一硬件上锁定这些设置，记录初始 LoRA 参数与首步样本/梯度哈希，并做至少两次完全相同配方的短程重复；目前的证据不足以指定某个 CUDA 算子为根因。

## 数据覆盖与泛化风险

638 条训练数据涉及 359 种工具，其中 **228 种只有一条**。按开发题所属工具的训练样本数做事后分组：训练中出现 3 次及以上的 42 题，严格正确 **13→18**；未见工具的 12 题 **4→4**，原生均分 **0.8241→0.7434**。这是覆盖不足的线索，不是因果证明；分组小且来自同一发布方 TRAIN 来源。发布方 `PASS_EXECUTED` 且 `ACCURATE` 的原始记录有 954 条；排除本轮 638 训练、128 开发和 64 封存 ID 后，还剩 124 条，其中 106 条在已筛选的本地 TRAIN 文件中。不能把这些条目自动视为高质量新 gold；用于新训练前需检查来源、近重复和命令语义。

## 当前结论与下一轮判定

**已确认的直接原因**是位置参数分下降抵消了工具和选项分的改善，以及 P04/P05 训练数值轨迹不一致。**尚未确认的根本机制**包括分叉由哪个算子导致、训练目标的空推理段是否改变命令选择、稀疏工具覆盖是否导致独立集退化。现有 128 题同源开发集的变化也不能证明外部泛化。

保持 E0 为正式底座，不推广 P05 或 P04。下一轮先做预先冻结的种子复核（P06，仍只看内部开发集），再根据复核结果设计数据质量和覆盖实验；独立验证及官方评测只能在候选和决策规则固定后进行。不能把官方 TEST 用来调参。
