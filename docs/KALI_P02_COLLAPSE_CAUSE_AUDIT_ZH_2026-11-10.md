# KaliBench P02 输出退化排查（2026-11-10）

## 已确认的故障

P02 在 128 道内部开发题中有 **126 道仅生成一个换行 token，下一步就生成 EOS**。这 126 道均未达到 1024-token 上限，也没有被截断；模型确实提前结束，而非评分器丢失命令。原模型在相同开发题上没有出现仅换行的回答。P02 的严格正确数为 **47/128 → 2/128**，格式错误为 **5 → 126**；此前 `1e-5` 的 638 条 SFT 在共同的 64 题上为 **28/64 → 30/64**。因此维持 E0，不采用 P02。这些题来自官方 TRAIN 的内部开发划分，不是 KaliBench 官方 TEST 结果。

训练编码核查表明，638 条监督目标都以“换行、`</think>`”开头，并以 EOS 结束。P02 能生成第一个换行，却在本应继续生成 `</think>` 的位置提前选择 EOS。这说明当前故障发生在模型的续写选择；仅凭输出还不能判断是哪个训练差异使 EOS 成为首选。

## 对照核查

- 已找回并核对两次运行各自真正执行的 Worker 哈希。P02 与此前表现较稳定的 638 条 SFT 使用**逐条相同的 638 条训练记录及顺序**，共同的 64 道开发题和四道基线锚点也相同；模型检查点、运行依赖、LoRA 配置及随机种子一致。四道锚点的原模型回答逐字相同；共同 64 题的原模型严格正确数均为 **28/64**，原生平均分均为 **0.756287**。
- 此前 SFT 的学习率为 `1e-5`，P02 为 `5e-6`。P02 还在训练前额外运行了 128 道基线推理，且两次运行分别落在 A100 PCIe 与 A100 SXM4 上。已用短时、只读 CPU 任务读取两份完整训练回执并清理任务：两者首步损失均为 **2.41219**，均完成 **638 步**、改动 **144 个 LoRA 张量**，且训练顺序哈希相同。此前 SFT 与 P02 的**最后 100 步平均损失**分别为 **0.3021** 与 **0.5229**；全程平均损失分别为 **0.7102** 与 **1.0110**。这比抽样日志更充分地支持 P02 拟合较弱，但仍不是提前 EOS 的单变量因果证明。
- 两份保存的 LoRA adapter 各有 **144 个 FP32 张量**，哈希均与训练回执匹配，重载探针的最大 logit 差为零。P02 的 LoRA B 张量总范数约为旧模型的 **75%**。这与更新较弱相符，但范数不能单独证明性能退化的原因。
- P01 的 `1e-5` 冒烟实验只有 **505 条训练记录、274 个工具**；638 条全集有 **359 个工具**。因此 P01 退化不能被当作“`1e-5` 学习率过高”的单变量证据。

## 已完成的学习率对照

P04 使用 P02 的同一 Worker、**字节一致的输入数据**、模型检查点、训练前 128 题基线推理、开发集和 A100-SXM4-80GB 型号；模型计算配置中只把学习率从 `5e-6` 改为 `1e-5`。首次排队约 70 分钟仍未获得 GPU，故安全取消；保留该记录后，第二次提交成功，完成 **638/638 个非零梯度步骤**，改动 **144 个 LoRA 张量**，adapter 重载最大 logit 差为零。P02 与 P04 在相同 128 题上的**训练前基线回答逐字一致**。P04 完整训练回执的最后 100 步平均损失为 **0.3016**，接近此前 `1e-5` 运行的 **0.3021**，低于 P02 的 **0.5229**。

| 同一 128 题内部开发集 | 原模型 E0 | P02：`5e-6` | P04：`1e-5` |
| --- | ---: | ---: | ---: |
| 严格正确 | 47 | 2 | 54 |
| 原生平均分 | 0.7550 | 0.2292 | 0.7757 |
| 格式错误 | 5 | 126 | 0 |
| 仅输出换行 | 0 | 126 | 0 |
| 正确的“换行、`</think>`”前缀 | — | 0 | 128 |
| 截断 | 0 | 0 | 0 |

P04 通过预先固定的五项开发集门槛；其中 11 题由错变对，4 题由对变错，训练未见工具的严格正确仍为 **4/12**。但第二块 64 题的原生平均分从 **0.7537 降至 0.7309**。在这 128 题上，严格正确变化的 McNemar 双侧精确检验为 **p=0.118**；配对原生平均分差 **+0.0207** 的固定种子 bootstrap 95% 区间约为 **[−0.0241, 0.0680]**。这些描述性不确定性计算不能把复用的同源开发集变成独立验证。

这次受控对照**强烈支持较低学习率是 P02 格式崩溃的触发因素**：提高学习率后，128/128 题都恢复了预期前缀，且不再出现提前 EOS。它仍只是一种训练配置下的一次对照，不能证明其他模型、数据或随机种子也会如此。P04 是操作员固定的因果诊断，协议明确禁止直接晋升为正式 ABA 候选；原生 ABA 训练运行中的 Broker 回执字段错误则是独立的编排问题。官方 TEST 与封存最终 64 题均未使用，**E0 仍是正式默认模型**。两次 CPU 审计和 P04 GPU Job 均已清理。
