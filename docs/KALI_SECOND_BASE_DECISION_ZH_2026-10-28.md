# KaliBench 是否换第二款模型复跑（2026-10-28）

## 结论

**需要一款第二底座做对照，但现在不应该把此前所有调试、训练和已揭晓评测原样重跑。**现有主实验仍以约 8B 的 RedSage-K-SFT-GRPO 为强领域模型；它已接受上游 KaliBench SFT/GRPO。第二底座推荐 [Qwen/Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)，作为通用模型的适配对照，而不是宣称它已经拥有 RedSage-K 的 KaliBench 排名。官方模型页显示公开权重、Apache-2.0，API 当前版本固定为 `b968826d9c46dd6066d109eabc6255188de91218`，参数 8,190,735,360。研究问题是：当起点还没有被 KaliBench 专项训练时，相同质量的数据与后训练能否产生可验证收益。

若目标是复现 RedSage-K 的上游训练链，官方[训练说明](https://github.com/RISys-Lab/KaliBench/blob/main/docs/training.md)指定另一款起点 `RISys-Lab/RedSage-Qwen3-8B-Ins`。本项目的第二模型对照优先选通用 Qwen，因为这能检查“领域模型剩余提升空间有限”这一解释；该对照不能直接视作官方 RedSage 复现。

## 已完成的无 GPU 预检

使用已固定版本的 Qwen3-8B tokenizer，对现有 240 条 TRAIN 的**全部题目**做了本机分词检查；没有打开 DEV、已揭晓确认集或官方 TEST 的正文。复核了 tokenizer 文件哈希、TRAIN 文件哈希、原生 Kali 提示词来源；没有下载模型权重、调用模型、执行命令或申请 GPU Job。

| 检查 | 结果 |
|---|---:|
TRAIN 题数 | 240 |
默认原生提示词 token 数 | 312–340 |
`enable_thinking=False` 提示词 token 数 | 316–344 |
提议的非思考模式目标拼接后最长 token 数 | 375 |
目标文本的 token 解码往返 | 240/240 通过 |
Qwen 默认提示词以 `<think>` 开口结尾 | **否**；以 assistant header 结尾 |
Qwen 非思考模式前缀包含已闭合空 `<think>` | **是** |
直接复用此前 RedSage-K worker 与输入哈希 | **不成立** |

此前 RedSage-K 训练器强制每条提示词以 `<think>` 结尾，并监督随后生成 `</think>`；Qwen3-8B 官方模板在默认模式下停在 assistant header。仅替换 `model_id` 会触发前缀/哈希断言，也会改变监督文本的结构。因此必须单独固定 Qwen 原生提示词、目标、分词数组和输出解析，再做**该模型内部**的训练前后配对比较。两款模型的绝对分数受提示词格式影响，不能解释为单纯权重差异。

## 后续实验的最小完整路径

1. 先由独立审核者检查训练候选的语义、等价答案和许可；建立与已用合成生成器分开的锁定保持集。现有 24 条保持题及 72 条确认题都已暴露，只能作开发诊断。
2. 锁定 Qwen3-8B 的原生提示词与目标格式、同一批获准 TRAIN、独立 DEV/保持题、固定评分代码和预算。**不能**直接复用 RedSage 的已编码 token 或现有模型专属 worker。
3. 只用一张普通优先级 GPU 做有限的 TRAIN-only 加载/格式预检，记录显存与输出；通过后再运行一次配对基线→固定 SFT→评测。训练前后需使用**相同**的 Qwen 推理协议。若要比较 ABA 的增益，另加与固定 SFT 使用相同数据预算的 ABA 组。
4. 在看输出前写好停止与采用门槛。独立保持集只在方案冻结后使用；官方 KaliBench TEST 留到最终阶段。若第二底座仍不能通过独立门槛，保留负结果，不反复调参后重测同一保持集。

当前 Nautilus 只读检查表明普通 Pod 配额尚未用尽，但**配额不是空闲 GPU 或立即排队成功的证明**。这轮没有提交 GPU Job，也没有产生新的模型结果。公共聚合记录只验证本机 tokenizer 预检；并不验证 8B 权重可在指定 GPU 上加载，更不说明新模型 SFT 有收益。
