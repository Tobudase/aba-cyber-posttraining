# ABA controller environment recovery — November 11, 2026

The existing persistent Linux VM could not attach its root storage volume because the cluster storage controller refused the connection. I tested a short-lived KubeVirt VM with a container disk and a sparse temporary work disk as an alternative. The successful bounded probe installed the pinned ABA source and dependencies, completed `aibuildai setup`, launched its CLI, and verified Python 3.12, a systemd user session with `memory`/`pids` delegation, and a working bubblewrap sandbox. The temporary work disk had roughly 11 GiB free after setup. The VM and its Pod were deleted after the check.

This establishes **controller installation feasibility**, not a completed ABA post-training run. A separate short probe used a pinned VM image to copy a harmless marker file from the temporary disk to protected local storage and verify its checksum before deleting the VM. That confirms a small-file recovery path; checkpoint-sized files and interrupted-run recovery remain untested. Before a research run, the model-control transport and GPU worker must be reconnected, and journals, model artifacts, and evaluation receipts must be copied to protected persistent storage before cleanup. No GPU, model API call, optimizer update, or official KaliBench TEST row was used in these environment checks.

The training-data audit also found a reason to keep the new source-silver labels quarantined: in the [KaliBench publisher verifier](https://github.com/RISys-Lab/KaliBench/blob/0b5bf54c9e343f94e113874b98ff5de815780328/src/data_creation/terminal_verify.py), `PASS_EXECUTED` means a command exited with code zero after error-pattern checks. It does not establish that the command fulfills the natural-language request. New labels need both version-matched execution and semantic checks before another exploratory SFT comparison.

The [ABA repository](https://github.com/aibuildai-inc/aibuildai-llm-posttrain-agent) documents its Linux, Python, cgroup and sandbox requirements. [KubeVirt's storage guide](https://kubevirt.io/user-guide/storage/disks_and_volumes/) documents that `containerDisk` and `emptyDisk` are temporary and explains their lifetime.
